# Морской бой

Морской бой с браузерной игрой против бота и REST-сервисом для турниров. Состояние партий хранится в PostgreSQL. Отдельная арена проверяет ответы по стартовой расстановке, ограничивает каждый HTTP-запрос одной секундой и проводит круговой турнир.

Стек: Python 3.12, FastAPI, SQLAlchemy 2, asyncpg, PostgreSQL 17, Alembic, HTTPX. Зависимости зафиксированы в `uv.lock`.

## Быстрый запуск

Нужен Docker с Compose v2. Скопируйте `.env.example` в `.env`:

```powershell
Copy-Item .env.example .env
docker compose up --build -d --wait api
```

В Linux/macOS первая команда — `cp .env.example .env`.

Compose запустит PostgreSQL, применит миграции и поднимет API. Данные сохраняются в Docker volume. База не публикует порт на хост; API доступен только на localhost.

- Игра: <http://localhost:{API_PORT}/>
- Swagger: <http://localhost:{API_PORT}/docs>
- OpenAPI: <http://localhost:{API_PORT}/openapi.json>
- Проверка процесса: <http://localhost:{API_PORT}/health>
- Готовность БД и схемы: <http://localhost:{API_PORT}/ready>

Создать партию:

```powershell
Invoke-RestMethod -Method Post http://localhost:{API_PORT}/game
```

Остановить сервисы, сохранив данные:

```sh
docker compose down
```

## Игра в браузере

Откройте <http://localhost:{API_PORT}/> после запуска Compose. Страница раздаётся самим API; отдельный сервер фронтенда и сборка JavaScript не нужны.

1. Перетащите корабли на своём поле или выберите корабль и нажмите нужную клетку. «Случайно» создаёт новую расстановку.
2. Для поворота выберите корабль и нажмите «Повернуть» или клавишу R. Корабли не должны соприкасаться, в том числе углами; недопустимый перенос сохраняет прежнее положение.
3. Нажмите «Начать бой», затем стреляйте кликами по полю противника. Попадание сохраняет ход, после промаха отвечает бот.
4. Обновление страницы восстанавливает начатую партию в том же браузере. «Новая игра» завершает текущую партию и возвращает к расстановке.

Сервер повторно проверяет флот и каждый выстрел. Во время боя расстановка противника скрыта; после завершения открывается. Партия хранится в БД, а её идентификатор — в localStorage браузера. Журнал показывает события текущего открытия страницы.

При обновлении проекта та же команда `docker compose up --build -d --wait api` применяет миграцию `0002` с таблицей браузерных партий.

### API браузерной игры

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/play/fleet` | Случайный корректный флот |
| POST | `/play/games` | Создать партию с пользовательским флотом: `{"ships": [{"coordinates": ["A1", "B1", "C1", "D1"]}, ...]}` |
| GET | `/play/games/{game_id}` | Восстановить состояние партии |
| POST | `/play/games/{game_id}/shot` | Выстрел `{"coordinate": "A1"}` и ответный ход бота |
| POST | `/play/games/{game_id}/close` | Завершить партию; повторное закрытие допустимо |

Ответ содержит `id`, `status`, `ships`, `shots`, `enemy_shots`; после победы — `winner`, после закрытия — `enemy_ships`. Подробные схемы доступны в Swagger. Параллельные ходы сериализуются блокировкой строки БД.

## API арены

| Метод | Путь | Ответ |
| --- | --- | --- |
| POST | `/game` | `201`, UUID сессии и полный флот |
| POST | `/game/{session_id}/shot` | Координата собственного выстрела |
| POST | `/game/{session_id}/shot/result` | Приём `miss`, `hit` или `killed` |
| POST | `/game/{session_id}/opponent-shot` | Результат выстрела по своему флоту |
| POST | `/game/{session_id}/close` | Закрытие сессии |

Все запросы выполняет арена. Повторное закрытие возвращает 400, обращение к закрытой игре — 410, неизвестная сессия — 404. Повтор входящего выстрела — 400, нарушение очередности — 409. После попадания или потопления очередь сохраняется.


## Тесты

Unit-тесты не требуют БД:

```sh
uv run pytest tests/unit
uv run ruff check .
uv run ruff format --check .
uv run mypy
```

Все unit- и интеграционные тесты в отдельном окружении:

```sh
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose -f compose.test.yaml down
```

Для тестов без Docker задайте `TEST_DATABASE_URL`. Имя БД обязательно заканчивается на `_test`: тесты очищают её таблицы, а проверка миграций удаляет и создаёт схему заново. Рабочую БД использовать нельзя.

## Архитектура проекта
- `src/battleship/domain` — правила, состояние партии, расстановка и тактика без БД и HTTP.
- `src/battleship/services` — игровые операции и границы транзакций.
- `src/battleship/db` — модели и конкретные SQL-запросы.
- `src/battleship/api` — контракт HTTP, схемы и обработчики ошибок.
- `src/battleship/static` — HTML, CSS и JavaScript игры против бота.
- `src/battleship/arena` — HTTP-клиент, судья, матч и турнир.
- `migrations` — версия схемы PostgreSQL.
- `tests` — unit, интеграционные, сетевые и нагрузочные проверки.
